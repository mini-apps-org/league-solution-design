25.3 F47 — Master division

Phase Status Rules
3 Target outline 04 §2 · Q5

25.3.1 Requirements

ID Requirement
FR-47.1 A division format "Master" that mixes 8-Ball and 9-Ball in one team night (for example, matches 1, 3, 5 in 8-Ball and 2, 4 in 9-Ball, set by bylaw)
FR-47.2 Each slot uses the player's SL for that slot's format; the team cap applies per format or as a combined index (to be decided)
FR-47.3 Team points are normalised so both formats weigh the same (for example, 8-Ball points × 20/3) or are kept separate in standings
FR-47.4 Accolades (including DOUBLE_STRIKE) count across formats in the same night

25.3.2 Key rules and assumptions

  • Builds directly on per-format SL (F32). No new scoring engine, only a slot → format map.
  • The put-up cap check must run with the format of the slot being filled.

25.4 F48 — Tournaments & brackets

Phase Status Rules
3 Target outline 04 §12 championship SL

25.4.1 Requirements

ID Requirement
FR-48.1 Admins create a tournament: format, singles or teams, bracket type (single elimination, double elimination, round robin + knockout), entry fee, dates, venue(s)
FR-48.2 Entry is open to qualified players or teams (F54) or to everyone, with payment through F36
FR-48.3 Seeding by standings or random; byes for non-power-of-two fields
FR-48.4 Each bracket match is an individual match scored with the live engine (E07); the winner advances automatically
FR-48.5 Public bracket page with live scores (F30) and a shareable link
FR-48.6 Handicap uses the player's championship SL (lowest attainable SL over recent sessions) where the rules say so

25.4.2 Key rules and assumptions

  • Reuse individual_matches and the event log; a tournament match has no team_match_id but a bracket_slot_id.
  • Double elimination needs a losers' bracket and a possible reset final.

25.5 F49 — Sandbagging detection

Phase Status Rules
3 Target outline R-124 · 04 §10

25.5.1 Requirements

ID Requirement
FR-49.1 A nightly job computes anomaly signals per player: sudden PPI drop, DS ratio outliers, high variance in innings per win, much better results in playoffs than in the regular season
FR-49.2 Signals above thresholds create anomaly_flags with the evidence (charts, match links) in an admin review queue
FR-49.3 Admin actions: dismiss (with reason), watch, raise SL (via F18 / F33), or refer to the league committee
FR-49.4 Flags are never visible to players; decisions are audited

25.5.2 Key rules and assumptions

  • Needs rich event data (innings, DS per turn) from E07; nights entered as final scores only are excluded.
  • Start with simple z-scores against the player's own history and the division; no ML until there's labelled data.

25.6 F50 — Multi-league & LO roles

Phase Status Rules
3 Target outline 04 §1 · 11 RBAC

25.6.1 Requirements

ID Requirement

FR-50.2 Roles become scoped: Platform admin (all leagues), League Operator (one league), Captain (team), Player

25.8 F52 — 10-Ball & 3-Cushion Carom

Phase Status Rules
3 Target outline 04 §2

25.8.1 Requirements

ID Requirement
FR-52.1 10-Ball: a call-shot game played as a race (like 8-Ball). Rack outcomes include legal 10, 10 on a foul (re-spot), break-and-run. Its own race chart and SL range
FR-52.2 3-Cushion Carom (popular in Vietnam): points per carom, match to a target per handicap, innings limit; the average (points ÷ innings) is the skill metric
FR-52.3 Formats are data: each format declares its scoring kind (race, points_target, carom), event types and reducer
FR-52.4 The live engine (E07) loads the reducer by format; the TS and Go reducers share fixtures as for 8- and 9-Ball

25.8.2 Key rules and assumptions

  • Carom doesn't fit the pool "rack" model: a match is a sequence of innings with points, so it gets its own reducer and UI.
  • Handicap tables must come from the league.

25.10 F54 — Championship qualification tracking

Phase Status Rules
3 Target outline 04 §12 championship lowest attainable SL

25.10.1 Requirements

ID Requirement
FR-54.1 Admins define qualification rules per championship: for example, the top 2 teams per division, a minimum number of matches played per player (e.g. ≥ 6 in the session), paid membership, and an SL rule
FR-54.2 The system shows each team's and player's qualification status live during the session: Qualified · On track · At risk · Not eligible, with the reason
FR-54.3 Championship lowest attainable SL: the lowest SL a player has held over the last N sessions is used for tournament handicap
FR-54.4 At the end of the session, the qualified list is frozen and feeds tournament registration (F48)

25.10.2 Key rules and assumptions

  • Uses standings (F35), per-player MP (F34) and SL history (F18).
  • Rules are data (qualification_rules jsonb) so they can change per championship.
