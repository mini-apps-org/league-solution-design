Phase 1 (MVP) skips the coin flip, the lag and live scoring. Home puts up first in match 1 and the sides alternate. R-031 Confirmed After Match 1, put-up order alternates between teams.

4.5.3 8-Ball points per individual match (3-point system)

Outcome Winner pts Loser pts
Shutout — loser won 0 games 3 0
Standard win — loser won ≥ 1 game but not on the hill 2 0
Hill-hill — loser on the hill (1 game short of their race) 2 1
text
points8(winnerGW, loserGW, loserGN):
  if loserGW == 0           -> (3, 0)
  if loserGW == loserGN - 1 -> (2, 1)   # on the hill
  else                      -> (2, 0)

Edge case: if loserGN == 2 and loserGW == 1, the loser is both "won ≥ 1" and "on the hill", so the result is (2, 1). The hill check takes precedence over the standard-win check.

A match therefore totals 3, 3 or 2 points, not always 3. The planned fn_score_individual_match() and the FE pointsFor() both implement hill = race − 1. One example in the original kickoff prompt ("4–2 when loser race 5 = 2/1") contradicts this and is treated as a typo.

ID Rule
R-070 Confirmed Maximum team points per night (8-Ball) = 5 × 3 = 15, plus the verification bonus (R-110).
R-071 Confirmed PA (Points Available) for 8-Ball = 3 per match played.

4.6 9-Ball rules

4.6.1 Ball values and targets

  • Balls 1–8 = 1 point each. The 9-ball = 2 points. Each rack totals 10 (counting dead balls).
  • Target points by SL:
SL 1 2 3 4 5 6 7 8 9
Target 14 19 25 31 38 46 55 65 75
ID Rule
R-080 Confirmed Points are attributed to the active shooter when a ball is legally pocketed.
R-081 Confirmed Dead balls (DB): balls pocketed on a foul (scratch, cue ball off table, illegal shot) count for neither player and are logged as DB so that Σ(points A + points B + dead) == 10 per completed rack.
R-082 Confirmed The 9-ball is never a dead ball. If pocketed on a foul, it is re-spotted (foot spot, or as close as possible). The app records nothing for that event apart from the foul.
R-083 Confirmed The match ends as soon as a player reaches their target. Recorded score is capped at the target (e.g. SL5 at 37 who makes the 9 on the break records 38, not 39).
R-084 Confirmed 9OB (9 on the break) and BR (break and run) are recorded as accolades. The ball points still count.
R-085 Confirmed Rack-close validation: a rack can be closed only when the 9-ball has been credited, i.e. the remaining unaccounted balls are auto-marked dead with confirmation.

4.7 Innings, defensive shots, timeouts

ID Rule
R-100 Confirmed An inning = one turn by each player. The counter increments when the player who lost the lag (i.e. the second shooter of the match) completes their turn. In the app this is triggered by Turn Over on that player.
R-101 Confirmed Turn Over is tapped when the shooter fails to pocket a legal ball (or otherwise ends their turn). It switches the active player.
R-102 Confirmed Defensive Shot (DS): any shot with no intent to legally pocket a ball. A DS is recorded per player; a DS is also a turn end (app action: DS implies TURN_OVER). Assumption The UI keeps them as separate buttons (as in APA). Pressing DS increments the counter and ends the turn.
R-103 Confirmed At the end of a match each player's total DS is shown. Zero renders as "No DS".
R-104 Assumption Timeouts per rack: SL ≤ 3 → 2; SL ≥ 4 → 1 (8-Ball). 9-Ball: SL ≤ 3 → 2; SL ≥ 4 → 1. Not in the sources; this is the APA default and is configurable per division bylaw. The UI shows N time-outs left.
R-105 Confirmed The scorekeeper/referee name is recorded per individual match.
R-106 The shot clock on Screen 5 (7 sec) is informational only (elapsed time since the turn started). No enforcement in Phase 1.

4.8 Score matching (verification) and bonus

TargetPhase 2. The MVP uses team_matches.status: scheduled → in_progress → submitted. A captain of either team (or an admin) submits once all 5 matches are complete, and admins may still edit afterwards. Who exactly may submit is an open question (Q30).

ID Rule
R-110 Confirmed Both teams must review and confirm the night's records. When both confirm matching records, each team receives a standings bonus: +1 (8-Ball), +10 (9-Ball).
R-111 With a single shared scoring device (MVP), "matching" means both captains confirm the same snapshot hash. With two devices (Phase 2), each team submits its own record set and the server diffs them field by field (GW, points, innings, DS, outcome codes).
R-112 Assumption Verification window: 24 h after the team match ends (configurable). After it expires, the match finalizes without bonus.
R-113 Confirmed Mismatches create a Dispute that the LO resolves in the admin portal. The resolution is audited and the bonus is withheld unless the LO grants it.

4.11 Identifier generation

BuiltAs-built: players.member_id and teams.team_number are free TEXT columns entered by an admin. The seed uses APA-style values (95007620, 03209), and the FE assumes 8-digit member IDs (MEMBER_ID_LENGTH = 8). The generators below are the Target Phase 2 target. Until then, admins must enter IDs that follow these formats (Q2/Q3).

4.11.1 Member ID (8 digits): YYMMNNNN

Part Meaning Example
YY 2-digit registration year 26
MM 2-digit registration month 11
NNNN Sequence within that month, zero-padded, from 0001 0042

Example: the 42nd player registered in Nov 2026 gets 26110042. Capacity is 9,999 per month.

Implementation: a Postgres table id_sequences(scope text primary key, last_value int) with UPDATE … RETURNING in the same transaction as the insert (gap-free, concurrency-safe). The scope key is member:2611.

4.11.2 Team ID (5 digits): RRVVT

Part Meaning Rule
RR Region code (2 digits) Derived from the host venue's district/postal region. The mapping table is managed by the admin. See Q3.
VV Host venue code (2 digits) Unique within the region
T Team sequence at that venue code 0–9
ID Rule
R-130 Confirmed All IDs are numeric only. Letters are used only if the numeric space is exhausted.
R-131 Confirmed A venue code holds max 10 teams (T = 0..9). When full, the venue is assigned an additional venue code (venue_codes 1-to-many), and new teams use the new code.
R-132 Display IDs (member_no, team_no) are immutable business keys. All foreign keys use UUID surrogate keys.
